# Design principles

The product's argument is that evidence beats an answer. The interface has to make
that argument too, or it undercuts it. These are the rules the UI is built to, and
the reasons — a rule without a reason gets broken the first time it is inconvenient.

---

## 1. It is a finding aid, not a dashboard

An archivist's working documents are paper: catalogue cards, accession registers,
finding aids. So the interface is warm paper and ruled lines, not cool grey and
floating panels. Identifiers, hashes and call sites are set in monospace because
they are things someone will copy into a catalogue record. Separation comes from
rules and fills, almost never from shadow.

This is not decoration. A tool that looks like a consumer AI product invites the
reading "the computer decided"; a tool that looks like a register invites "here is
what was found, and where." The second reading is the true one.

## 2. Colour is meaning, never decoration

Five colours, each with exactly one job:

| Token | Job |
|---|---|
| `--accent` | interactive, and only interactive |
| `--pass` | a threshold met, a citation confirmed |
| `--warn` | provisional, unaudited, or a caution the reader must act on |
| `--crit` | refused, contradicted, sealed |
| ink / faint | everything else |

If something is coloured and is neither a control nor a verdict, it is a bug.
Every foreground/background pair in `styles.css` is checked against WCAG AA in
both themes — body text at 4.5:1, labels and large text at 3:1. The audit is
reproducible; the worst pair in either theme is 3.50:1 on a non-text label.

## 3. Uncertainty is designed, not degraded

`abstain` is the correct answer for two of the ten demo fragments and will be the
correct answer for a great deal of real material. It must never inherit error
styling. The abstain verdict gets a neutral, deliberate, fully-designed panel —
the same weight as a probable identity — because the product's headline metric is
*zero false-confident identifications*, and an interface that renders "I don't
know" as a failure teaches the opposite lesson.

The same applies to a fragment that stays unidentified: it gets an action (leave a
standing watch), not a dead end.

## 4. Evidence carries its standing visually

A reader should be able to tell a confirmed source from a refused one without
reading a word. A source that passed the live Extract audit sits on a solid
green-edged card; one that failed is dashed, dimmed, and labelled *refused by the
gate*. Rejected citations get their own block with the reason.

This is the most important rule in the file. The product's whole claim is that a
fabricated citation can only ever weaken a verdict — if the interface renders a
good and a bad citation identically, the claim is invisible and might as well be
untrue.

## 5. Nothing asserts a status it has not checked

The sponsor stack ribbon appears on every page and reads from `GET /v1/stack`.
A service that is unreachable is shown as unreachable, on every page, at once.
There is no hardcoded "powered by" list anywhere in the markup, because a static
logo row is a claim the interface cannot back up.

## 6. The wait is the explanation

An investigation takes 225–430 seconds, median 383, measured across the five
development fragments with the credential attached. A spinner for six minutes reads
as a hang and teaches nothing. The run console names all six stages, says which agent
owns each one and which Parallel surface it calls, runs a real elapsed clock, and
states the expected duration *before* the clock starts.

That last part was a correction. The stage timings were first written from an
estimate totalling 100 seconds; the measurement came in at nearly four times that,
so the console reached its final stage in under two minutes and then sat on it for
four more — producing exactly the hang-reading the console exists to prevent. The
figures are now the original proportions rescaled to the measured median. A design
that explains the wait has to be right about how long the wait is.

The stage cadence is a timer, not a live trace — the API returns one response at
the end, so there is no per-stage event to bind to. So the console describes the
pipeline's shape and never claims a stage produced a result. When the response
lands it replaces the console entirely.

## 7. A worked example is never mistaken for a run

The evidence board is the product, and until the Parallel credential is attached
nobody can see one. `GET /v1/example/dossier` returns one. It is safe because:

- the fragment is invented and the candidate film does not exist, so nothing real
  can be misattributed;
- every source is an RFC 2606 reserved domain that can never resolve;
- it is generated by the *real* evidence builder and the *real* gate, so it cannot
  drift into depicting behaviour the software no longer has;
- the banner is sticky inside the board and the panels go dashed, so it cannot be
  scrolled out of frame and screenshotted as a result.

It also deliberately returns `candidates`, not `probable` — the example shows the
gate *refusing*, which is the behaviour worth demonstrating.

## 8. Two reading modes, both real

Plain and Technical are a genuine content switch, not a jargon toggle. Plain
explains to an archivist; Technical explains to an engineer. Neither is a summary
of the other, and the switch is remembered.

## 9. It prints

Archivists print dossiers and file them. The print stylesheet drops navigation and
controls, un-collapses the agent outputs, avoids breaking a claim across pages, and
writes every citation's URL out in full after its link — a printed citation without
its URL is worthless five years later.

## 10. Accessible by construction

- Every interactive control is a real `<button>`, `<a>`, or form element.
- Status carried by colour is also carried in the accessible name: the ribbon chips
  say "reachable now" / "not reachable", because a coloured dot and a `title`
  tooltip reach neither a keyboard nor a screen-reader user.
- `[hidden]` beats every component's own `display` rule, so a hidden tab pane is
  actually hidden.
- Focus is visible everywhere: a 2px accent outline with offset, never removed.
- `prefers-reduced-motion` disables all animation and smooth scrolling.
- Two sticky bars, so `scroll-padding-top` clears both and an in-page anchor never
  lands underneath them.
- The layout works from 320px up; the ribbon stops being sticky on small screens
  rather than eating a third of the viewport.

---

## Tokens

Defined once at the top of `app/web/styles.css`. Spacing is a 4px scale
(`--s1`…`--s9`). Type is a fluid scale (`--t-micro`…`--t-hero`) with three
families: a grotesque for UI, a serif for reading prose, a monospace for data.
Dark mode redefines only the colour tokens.

Change tokens, not component rules. If a component needs a value that is not in
the scale, the scale is probably wrong.
